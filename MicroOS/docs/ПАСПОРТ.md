- **MQTT**: `CFG_EVENT_CHANGED` теперь зеркалится как `events/CFG_CHANGED`
  (триггер внепланового снимка; payload — ключ поля).
- Обратная совместимость: замок и шлюз собираются на 5.8.5 без правок
  (контрольные сборки зелёные: lock 1096450 Б, gate 1082278 Б).

### home_master 0.5.2 → 0.6.0 (9 файлов + панель)
- **BackupService** (новый модуль 0x1107): цикл съёма по хостам из
  `bk.hosts` — login → export → SD `/backup/<ip>/config-YYYYMMDD-HHMMSS.json`
  + `latest.json`, tmp+rename, ротация `bk.keep` (дефолт 10).
- **Расписание:** `bk.period_days` (дефолт 7; unix-время, не millis —
  урок переполнения 49 суток). Первый съём — через 10 мин после старта.
  Внепланово: ~5 мин после `CFG_CHANGED` в парке (`bk.on_change`).
- **Стражи:** нет достоверного времени — плановый съём молчит; 401 от
  устройства — хост блокируется до смены `bk.admin_pin` (мастер не имеет
  права быть источником rate-limiter блокировки админки!); SD нет —
  тихая деградация; `old_fw` для устройств без ядра 5.8.5.
- **ПАЗ:** новая проверка `hm.bk` (Warning при беде хоста).
- **Панель:** новая профильная вкладка **💾 Бэкапы** (между Журналом и
  Настройками): статусы хостов, «Снять сейчас», список снимков,
  «Развернуть» (с подтверждением — устройство перезагрузится).
- **Должок закрыт:** дубль ModuleId 0x1104 — JournalService → **0x1106**
  (комментарии в BridgeService/WeatherMirror обновлены).
- Группа конфига **«Бэкапы»** (`bk.*`) — в конце схемы, живые поля
  (CFG_NONE): вкладка ⚙️ Настройки.

## Сборка и прошивка

Мастер: чистая сборка (правило 20), fqbn как обычно; контрольный размер
у нас: **1110032 Б** (Sketch uses), globals 99293 Б. ФС пересобрать

   администратора устройств парка (поле секретное, NVS).
2. Если пароли админов на устройствах РАЗЛИЧАЮТСЯ — скажите: сделаем

## Приёмка (предложение)

1. Вкладка 💾 Бэкапы: хосты видны, статусы честные.
2. Через ~10 мин после старта (или «Снять сейчас») — снимки на SD,

# ПАСПОРТ — Ядро 5.8.7 «честный ПАЗ-сигнал» (общий релиз флота)

## Что в ядре (2 изменения + версия)

### 1. Подтверждение переходов проверок (перенос ConfirmState в ядро)
Каждая зарегистрированная проверка любого профиля теперь меняет статус
только после K подряд одинаковых прогонов:
- `paz.confirm_bad` (1..10, дефолт 3) — ухудшений до тревоги;
- `paz.confirm_ok`  (1..10, дефолт 2) — улучшений до снятия тревоги.
Новые ключи — группа «Система» (в схеме ядра, после существующих).
«Мигающая» проверка больше не крутит счётчики и не спамит событиями.
Встроенные heap/термо/дежурные НЕ затронуты — у них свои автоматы.
Профиль мастера 0.6.9: ConfirmState демонтирован, проверки возвращают
сырой вердикт — поведение идентично 0.6.8 при дефолтах.

### 2. Свёртка TICK_OVERRUN
Было: +1 warn за КАЖДЫЙ тик модуля сверх бюджета 50 мс, без строки в
логе (приёмка 0.6.8: warn 6→23 при чистом журнале — шум, не состояние).
Стало: всплеск = ОДНО предупреждение с записью в лог
«tick overrun: <модуль> <мс> (начало всплеска)»; повторные тики всплеска
— только статистика; 60 с тишины — recovered с итогом
«всплеск закрыт (<модуль>), тиков N, макс M ms».

### 3. Версия ядра 5.8.7 (метка MICROOS|5.8.7|END в .bin).

## Порядок перепрошивки (по принятой в 0.6.5 цепочке)
1. МАСТЕР — первым, вручную (он раздаёт); после прошивки ПИН администратора
   и пароль брокера НЕ слетят (они в NVS, а не в конфиге — 0.6.6/ПРАВКА 2).
2. Тройки замка и шлюза — конвейером, загрузить на мастер (ручная

3. Парк обновляется по OTA с мастера, конфиги восстановить из бэкапов.
4. Прошивка+ФС парой, если менялись обе (в этом релизе менялось только
   firmware; ФС мастера — ПРАВКА 1 из комплекта 0.6.8 по желанию).

## Приёмка
1. Каждое устройство: бут-лог сообщает 5.8.7, панель → Система —
   поля «ПАЗ: плохих/хороших прогонов» видны и меняются.
2. Мастер, нагрузка (ручная загрузка троицы, «Снять всё» в бэкапах):
   в логе ОДНА строка «tick overrun: ... (начало всплеска)», через минуту
   тишины — «всплеск закрыт ... тиков N, макс M ms»; warn +1 за всплеск,
   не +N.
3. Мастер, молчание замка <3 мин: тревоги нет; ≥3 мин: hm.fleet Warning;
   весь парк молчит: Critical (как в приёмке 0.6.8).
4. Замок/шлюз: ПАЗ зелёный, данные текут, warn-счётчик стабилен в покое.

## Что в ядре (2 изменения + версия)

### 1. Подтверждение переходов проверок (перенос ConfirmState в ядро)
Каждая зарегистрированная проверка любого профиля теперь меняет статус
только после K подряд одинаковых прогонов:
- `paz.confirm_bad` (1..10, дефолт 3) — ухудшений до тревоги;
- `paz.confirm_ok`  (1..10, дефолт 2) — улучшений до снятия тревоги.
Новые ключи — группа «Система» (в схеме ядра, после существующих).
«Мигающая» проверка больше не крутит счётчики и не спамит событиями.
Встроенные heap/термо/дежурные НЕ затронуты — у них свои автоматы.
Профиль мастера 0.6.9: ConfirmState демонтирован, проверки возвращают
сырой вердикт — поведение идентично 0.6.8 при дефолтах.

### 2. Свёртка TICK_OVERRUN
Было: +1 warn за КАЖДЫЙ тик модуля сверх бюджета 50 мс, без строки в
логе (приёмка 0.6.8: warn 6→23 при чистом журнале — шум, не состояние).
Стало: всплеск = ОДНО предупреждение с записью в лог
«tick overrun: <модуль> <мс> (начало всплеска)»; повторные тики всплеска
— только статистика; 60 с тишины — recovered с итогом
«всплеск закрыт (<модуль>), тиков N, макс M ms».

### 3. Версия ядра 5.8.7 (метка MICROOS|5.8.7|END в .bin).

   # ПАСПОРТ КИТА — МикроОС 5.9.5 / home_master 0.8.0 «сторож тишины»

**Дата сборки:** 14.09.2026
**Основание:** дополнение 4 ветки weather_gate (14.09) — новый класс отказа «RX жив, пакетов нет» + просадки heap под входящим HTTP.

## Состав

- `micro-os-5/` — исходники со структурой репозитория (src/ + library.properties + projects/home_master). Дерево сверено с каноническим репозиторием побайтово.
- `бинарники/firmware.bin` — прошивка (1 163 776 Б), метки `MICROOS|5.9.5|END` и `MICROOS|5.9.5|0.8.0|END` проверены grep по .bin.
- `бинарники/littlefs.bin` — образ ФС (3 538 944 Б).
- `бинарники/version.json` — манифест OTA (md5 обоих образов внутри).

## Что нового в ядре 5.9.5

1. **Сторож «RX, но тишина» в драйвере CC1101.** Критерий: хотя бы один пакет за аптайм был, MarcState=RX (штатно), но валидных пакетов нет дольше `rf.silence_min` минут (по умолчанию 15; 0 = выключен). Лечение — та же полная переустановка приёмника, что у MarcState-сторожа: SIDLE → SFRX → таблица → SRX. Перевооружение не чаще порога. Факт — в Serial (`сторож тишины: пакетов нет N мин…`) и счётчик `rfSilenceFixes()` для ПАЗ/панели профиля.
2. **Крупнейший свободный блок heap в диагностике.** Строка `HEAP new min` (HealthMonitor) и часовая строка `net health` (NetworkManager) теперь несут `max block N` — различие «фрагментация vs расход»: minFree низкий при здоровом max block = память съедена; max block просел вместе с minFree = куча фрагментирована.

## Порядок прошивки

Ядро затронуто → весь флот перешивается, **мастер ПЕРВЫМ вручную**. Прошивка и ФС шьются парой. Профильные образы уйдут на замок и шлюз с мастера (шлюз собирает своя ветка — ядро 5.9.5 уже в main).

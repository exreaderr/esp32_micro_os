## 1. Оверлей перезагрузки (панель, index.html)
Сессии администратора скользящие (30 мин, продлеваются каждым запросом) и
RAM-only — это осознанная модель безопасности, НЕ меняется. Меняется UX:
любой ответ API с полем `reboot_in_ms` (перезагрузка, self-restore, импорт)
теперь автоматически поднимает оверлей «🔄 Перезагрузка»: панель ждёт
возвращения устройства (опрос /api/system), затем честно показывает окно
пароля с подписью «Перезагрузка завершена — войдите снова». Внезапного
«сессия слетела» больше нет. Из cfgSave/doReboot/doRestore убраны
самодельные таймеры location.reload — потоком владеет оверлей.

## ПРАВКА от 05.09 (приёмка, прогон 2) — WDT-bootloop OtaMirrorService
Симптом: ребут каждые ~2 минуты, task_wdt loopTask, «last tick:
OtaMirrorService». Корневая причина: цикл скачивания `while(connected())`
ВИС на keep-alive HA (соединение открыто после последнего байта), WDT 10 с
перезагружал кристалл; плюс «манифест+2 скачивания» в одном тике превышали
бюджет WDT. Исправлено: шаг хоста разбит на фазы по тикам (0=манифест,
1=fw, 2=fs, 3=коммит), цикл скачивания выходит по Content-Length +
сторожа stall 2,5 с / cap 7 с, таймауты 4 с. Урок: ручной цикл чтения HTTP
выходит по Content-Length/закрытию, не по connected().
В состав комплекта добавлены OtaMirrorService.h/.cpp (исправленные).
Контроль после перепрошивки: аптайм растёт дальше 3 минут, в логе
«OTA-зеркало: smart_lock -> x.y.z», «weather_gate -> x.y.z».
Сборка правки: 1121572 B (85%), RAM 32%.

# ПАСПОРТ — МикроОС 5.9.6 / home_master 0.8.9 «W7: пейсинг из конфига»

Дата сборки: 02.10.2026. Ядро 5.9.6 (без изменений). Профиль home_master
0.8.9. Цель: Waveshare ESP32-S3-POE-ETH (10.146.75.54).

## Причина выпуска

Полевой тест 02.10 (вечер): пейсинг 0.8.8 подтверждён на проводе
(MQTT Explorer: дельта ровно 0,2 с), но шлюз принял 86/210, затем
160/210 на ретрае. Дренаж шлюза измерен ~2 кадра/с: его loop во время
восстановления занят dlog-записью в LittleFS и стартовыми задачами —
даже 200 мс/кадр переполняет однослотовый mailbox.

Исправление:
- Пейсинг вынесен в конфиг: **arch.pace_ms** (новое поле в КОНЦЕ группы
  «Архив W7», UINT 100–2000, дефолт **500**, критичное — ребут).
  210 кадров ≈ 105 с. Подстройка дальше — без пересборки.
- Сторож сессии 120 → 240 с (сессия теперь длиннее + переспросы).

Требование к шлюзу (ветка weather_gate, 0.9.6): таймаут сборки 60 →
150 с; рекомендовано отложить dlog-запись принятых кадров (буфер +
флаш пачкой) — тогда дренаж вырастет и pace_ms можно будет опустить
до 200–300 мс прямо из веб-морды мастера.

По ходу сборки гремлин съел правку версионного комментария — пойман
grep-контролем.

## Состав и контроль

- `micro-os-5/` — исходники (ядро 5.9.6 + профиль 0.8.9).
- `бинарники/`: firmware.bin (1 171 728 Б, md5 `da85f62777de918fc4bf626248f9b30e`),
  littlefs.bin (md5 `96d461d00771ea096f297142d3f4211d`), bootloader,
  partitions, boot_app0, version.json (двухполевой манифест).
- Строки в бинарнике: «5.9.6» ×3, «0.8.9» ×2.

## Прошивка

Ядро не затронуто — перешивается ТОЛЬКО мастер (FW+FS парой; можно через
зеркало: тройка → карточка «5.9.6 · профиль 0.8.9» → обновить).
ВАЖНО: новое поле критичное — после прошивки мастер перезагрузится на
записи конфига (штатно). Проверить во вкладке «Архив»: группа «Архив W7»
теперь с полем «Пауза между кадрами выдачи, мс» = 500.

Контроль теста: шлюз 0.9.6 (таймаут 150 с) → приём 210/210 за ~110–120 с;
в MQTT Explorer дельта ~0,5 с.

# ПАСПОРТ КИТА — МикроОС 5.8.8 / smart_lock 0.5.15 «Двухполевая версия OTA»

Дата сборки: 08.09.2026
Основание: одобрено владельцем 08.09.2026.

## Что в ките

- `micro-os-5/src/` — ядро 5.8.8 целиком (структура репозитория).
- `micro-os-5/projects/smart_lock/` — профиль 0.5.15 целиком (вкл. data/).
- `бинарники/` — firmware.bin + littlefs.bin + version.json (с полем
  `profile_version`).

## Отвязка шкалы профиля от ядра (5.5.15 → 0.5.15)

Старая нумерация замка (5.5.x) — наследие времён, когда версия профиля
совпадала с версией ядра. С 5.8.8 ядро и профиль — две независимые шкалы.
Решение владельца 08.09.2026: «оставить 5.15, а в начале добавить 0 —
будем видеть, что это профиль, но прошедший определённый путь в своём
развитии». Ведущий 0 = версия ПРОФИЛЯ, хвост 5.15 — сохранённая история.

ВАЖНО для сверки OTA: 0.5.15 МЛАДШЕ 5.5.15 по semver. Поскольку на флоте
замок с 5.5.15 (ядро 5.8.7), переход на 5.8.8+0.5.15 срабатывает по ветке
«ядро новее» — обновление предложит по ядру, профиль придёт в комплекте.
Внутри 5.8.8 сравнение профилей дальше пойдёт по новой шкале (0.5.16,
0.6.0…) без изъянов. Одноразовый переход.

## Ядро 5.8.8 — что изменилось (общее для флота)

Двухполевая версия OTA: сверка «ядро новее ИЛИ (ядро равно И профиль
новее)», даунгрейд по любому полю не предлагается. В .bin две метки:
`MICROOS|5.8.8|END` и `MICROOS|5.8.8|0.5.15|END` (проверено grep'ом).
Полный список изменений ядра — в паспорте кита мастера.

## Профиль smart_lock 0.5.15

- `MICROOS_PROFILE_VER 0.5.15` в шапке SmartLockApp.h — единственный
  источник версии профиля; getVersion() отдаёт тот же макрос строкой.
- init(): `setProfileVersion(getVersion())` + boot-лог `bin tag: …`.
- Панель: карточка OTA показывает «ядро · профиль», различает
  «Доступно обновление ядра» / «…профиля».

## Приёмка

Обновление с мастера (тройка из `бинарники/` этого кита), конфиг из
бэкапа. Панель: «Текущая прошивка 5.8.8 · профиль 0.5.15». Boot-лог:
`bin tag: MICROOS|5.8.8|0.5.15|END`.

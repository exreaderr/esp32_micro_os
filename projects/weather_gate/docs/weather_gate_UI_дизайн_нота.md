# Дизайн-нота — weather_gate: веб-оболочка wx.html, контраст и плотность (UI-этап)

10.10.2026. Инициатор: владелец. Статус: на согласовании.

## Диагноз (обмеры wx.html против lock.html)

Оба файла — самодостаточные оболочки настроек профиля (ядро отдаёт
только тёмную служебную страницу; светлая оболочка — территория
профиля, **ядро не затрагивается**). Базовая палитра у обоих одна
(тёплая экосистемная), различия — в том, как она использована:

| Аспект | wx.html (сейчас) | lock.html (эталон концепции) |
|---|---|---|
| CSS | 8,8 КБ, 1 медиазапрос | 25 КБ, 4 медиазапроса |
| Кнопки | «призраки»: рамка --border, без заливки, цвет текста --text2 | залитые акцентом, семантика info/success/warning/danger/svc, hover +7% яркости, active scale(.97) |
| Фокус полей | только смена цвета рамки | рамка + кольцо-тень rgba(--info,.16) |
| Сетка | 3 grid-правила, 1 брейкпоинт 640px | 12 grid-правил, брейкпоинты 380/760/1000 |
| Плотность | карточки padding 14–16px, поля в одну колонку | двухколоночные формы от 760px, компактные отступы |

Жалобы владельца точно ложатся на обмеры: кнопки-призраки
нечитаемы на --card #fffdf6; поля тянутся в одну колонку на всю
ширину — «рыхлость».

## Предложение

Переносим КОНЦЕПЦИЮ замка (не код и не скины metro/term — их у
шлюза нет и не нужно):

1. **Кнопки — залитые, семантические.** Основные действия
   («Сохранить параметры», «Обновить», «Проверить обновление») —
   заливка --info, белый текст, font-weight 600. Служебные —
   --svc. Опасные («Перезагрузить», стирание) — --error. Классы
   .small для кнопок в строках статуса. Hover/active как у замка.
2. **Фокус полей** — рамка + мягкое кольцо-тень (видно, куда
   нажал, особенно на смартфоне).
3. **Двухколоночные формы от 760px**: пары «метка+поле» пакуются
   в сетку 2 колонки (как «Длительность блокировки / Неудач до
   блокировки» у замка); от 1000px — вкладки-настройки в две
   колонки карточек там, где карточки короткие (Система, Админ).
4. **Плотность**: вертикальные отступы полей ужимаются
   (margin-bottom 10px вместо разрозненных), label остаётся
   10px uppercase — система уже привычная.
5. **Мобильный порог 380px**: минимальные паддинги карточек,
   кнопки на всю ширину — сценарий «настройка с телефона».
6. **Палитра и радиусы не меняются** — оболочка остаётся
   узнаваемо «погодной», меняется только контраст и компоновка.
   Тёмная тема (body.dark) получает симметричные правки.

## Границы

- Трогаем ТОЛЬКО projects/weather_gate/data/web/wx.html (CSS +
  точечные классы в разметке). JS-логику не меняем; node --check
  извлечённого JS — обязателен.
- Ядро, uPlot, вкладка «Графики» (uPlot-панель) — вне объёма,
  кроме переключателей диапазонов/метрик (это те же кнопки).
- Ничего не уезжает во флэш приложения: wx.html живёт в LittleFS —
  обновление только образом ФС (bin не трогаем, version профиля
  поднимем как 0.9.10-ui: маркер в ФС, прошивка остаётся 0.9.9).

## Приёмка

- Чек-лист глазами владельца: кнопки видны без приглядывания на
  всех 5 вкладках; формы Система/Админ/Радио — двухколоночные на
  десктопе; на смартфоне (≤380px) ничего не липнет к краям.
- Ворота: host-тесты 44060 PASS/0 FAIL (wx.html не покрыт тестами —
  норма не падает), node --check JS, компиляционный прогон 4
  профилей последовательно (бинари не меняются — прогон для
  чистоты), ФС round-trip 3/3, readback метки в образе ФС.
- Доставка: новый littlefs.bin + обновлённый src.zip.

## Риски

- Регрессия вёрстки на вкладках с нестандартными блоками (журнал
  ПАЗ, графики) — лечится покадровым визуальным прогоном после
  прошивки ФС (скриншоты 5 вкладок, как обычно).
- Рост wx.html (~+6–8 КБ) — LittleFS 1,4 МБ, запас огромный.

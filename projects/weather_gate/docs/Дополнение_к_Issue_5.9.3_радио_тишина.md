# Дополнение 4 к запросу: новый класс отказа — «RX жив, пакетов нет» (ядро 5.9.3, прогон 13–14.09)

Дата: 14.09.2026
От: ветка weather_gate
К Issue: «Запрос к ядерной ветке: два дефекта автономности» от 10.09.2026
(доп. 1 — пул сокетов; доп. 2 — RAW PCB; доп. 3 — сокетный слой/ENFILE).

## Эпизод: радио молчало ~2 часа, сторож MarcState не смог помочь

Хронология (аптайм бута, монитор порта непрерывен):

```
[33488318] check wg.radio: WARNING RADIO_SILENCE        (~9,30 ч)
[34388418] check wg.radio: CRITICAL RADIO_DARK          (~9,55 ч)
[34801921] HEAP new min: 14312 bytes                    (~9,67 ч)
[34862105] tick overrun: AuditService, 689 тиков, макс 973 ms
[34879163] tick overrun: HttpService 280 ms (×2 всплеска)
[38684985] tick overrun: HttpService 336 ms             (~10,75 ч)
[38712817] HEAP new min: 12324 bytes                    (глобальный минимум!)
[40931395] check wg.radio: recovered                    (~11,37 ч, САМО)
[41841691] WARNING RADIO_SILENCE → CRITICAL RADIO_DARK → recovered
           (короткий повтор ~15 мин)
```

Факты:
1. Приёмник всё это время был в RX — сторож MarcState (!=RX → переустановка)
   молчал штатно, ловить было нечего. Но пакетов не было ~2 часа
   (уличный блок шлёт каждые ~48 с). Новый класс отказа:
   **«MarcState = RX, но тишина»**.
2. Восстановление самопроизвольное, БЕЗ переустановки приёмника —
   железо живо, деградировала цепочка приёма/учёта.
3. Эпизод совпал с двумя «штурмами» панели (владелец циклически
   переключал графики — управляемый эксперимент): рекордные просадки
   кучи (14312, затем 12324 байт — глобальный минимум всех прогонов)
   и секундные overrun'ы HttpService/AuditService. Мгновенного эффекта
   не было; тишина началась ДО первых зафиксированных всплесков —
   причинность по одному логу не доказать, но корреляция
   «тяжёлые JSON ↔ просадки heap ↔ аномалии» повторяется.
4. Отдельный тренд: глобальный heap-минимум падает от прогона к прогону:
   17128 → 16100 → 14312 → 12324. Каждый штурм графиков пробивает дно
   ниже. До критических для ESP32 значений ещё далеко, но вектор плохой.

## Просьбы к ядерной ветке

1. **Сторож «RX, но тишина»** в драйвере CC1101 (или мост от ПАЗ):
   если MarcState = RX, но валидных пакетов нет T минут (наш порог
   RADIO_DARK в ПАЗ — CRITICAL уже считается) → SIDLE → SFRX → таблица →
   SRX (та же переустановка, что у MarcState-сторожа). Порог просим
   конфигурируемым (наш сценарий: тишина > 10–15 мин при живом блоке —
   уже отказ; RADIO_DARK наступает раньше).
2. **Просадки heap под входящим HTTP:** большие JSON-ответы dlog
   (json buf 24576) при опросах панели каждые 15–30 с — главный
   кандидат на фрагментацию/пики. Просим оценить: пагинация/лимит
   dlog-ответа или принудительный caps на размер выдачи. На уровне
   профиля можем лишь увеличить интервал опроса панели — но буфер
   выделяется ядерным HttpService/dlog.
3. Связь с сокетной утечкой (доп. 3) возможна общим корнем: оба симптома
   живут под входящей HTTP-нагрузкой. Часовая строка net health 5.9.4
   (sock_free + accepts) покажет.

## Статус прогона

Шлюз на 5.9.3 (5.9.4 получен, прошьём парой с выходом). Сокетного клинча
в этом окне не было (аптайм ~12 ч, эпизод радио закрылся сам). Монитор
порта пишет третьи сутки. LED-индикация (0.7.1, GPIO2) работает штатно,
цвета соответствуют ПАЗ.

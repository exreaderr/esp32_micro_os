## Механика залипания (pcap, Mikrotik, зеркало трафика шлюза)

Трасса к api.open-meteo.com (94.130.142.35:80), сессия sport=57899:

3. **Сервер молчит: ни ответа, ни FIN, ни RST — вообще ничего.**
4. GW: ретрансляции GET, затем повторные FIN с растущим бэкоффом:

Интерпретация: `close()` профиля уходит в FIN_WAIT_1, lwIP ретранслирует
FIN по таймеру и **никогда не сдаётся** — сокетный слот и буферы заняты
до ребута. Одна такая сессия в час → ровно −1 слот/час → ENFILE (errno 23)
через ~13 часов (13 свободных слотов из 16). Арифметика окон клинчей
(13,04 / 13,13 / 13,17 / 14,1 ч) подтверждена.

Сравнение с здоровой сессией 57898 того же часа: GET → ответ 542 Б ×2 →
сервер сам закрывает FIN через ~46 с — всё чисто.

## Фикс (профиль weather_gate 0.7.3, ядро не тронуто)

`abortHttpSession()` в WeatherGateApp.cpp, вызывается перед `http.end()`
в `forecastTask` и `altitudeTask`:

```cpp
struct linger lng = {1, 0};
setsockopt(client.fd(), SOL_SOCKET, SO_LINGER, &lng, sizeof(lng));
http.end();
client.stop();
```

SO_LINGER {1,0} превращает close() в RST: слот и буферы освобождаются
немедленно, независимо от молчания сервера. Ответ к этому моменту уже
прочитан до конца — RST безопасен.
